## 1. المبادئ الحاكمة

ستة مبادئ غير قابلة للتفاوض، كل واحد منها جاء من عيب قِستُه فعلًا:

1. **«لا صفقة» هي الحالة الافتراضية.** النظام `fail-closed`: القرار يبدأ `NO_TRADE`
   ولا يتغيّر إلا بأدلة كافية مرّت بكل البوابات. انقطاع أي بوابة = `NO_TRADE`، لا «تقدير».
2. **بيانات القرار من الوسيط وحده.** `bid/ask` ومواصفات العقد الحقيقية من MT5/XM.
   TradingView والأخبار = سياق وعرض، لا قرار. (عيب 2: السبريد وحجم العقد يختلفان بين الرموز.)
3. **لا رقم بلا أصل.** كل قيمة تحمل: المصدر، وقت الحدث، وقت توفّر المعلومة، التأخر، الترخيص، البصمة.
4. **رمز التحليل ≠ رمز التنفيذ.** الحجم يُحسب **دائمًا** من مواصفات رمز الوسيط المستهدف. (عيب 2.)
5. **سلطة المخاطر لا تُشارَك.** حارس المخاطر يملك حق النقض المطلق ولا وكيل يملك تعديل حدوده.
6. **لا ترقية تلقائية.** الانتقال بين المراحل بموافقتك الصريحة المكتوبة فقط.

## 3. الفريقان: المدخلات والمخرجات وحلّ الخلاف

لا يوجد وكلاء سابقون لأطوّرهم (المجلد كان فارغًا)، فهذه الأدوار جديدة.
**7 أدوار فقط، لا 14** — دمجتُ ما لا يحتاج شخصية منفصلة.

### فريق النظام

| الدور | المدخل | المخرَج (عقد التسليم) |
|---|---|---|
| **المعماري** | المتطلبات، نتائج التدقيق | قرارات معمارية مُرقَّمة (ADR) في `docs/decisions/` |
| **مسؤول البيانات والصلاحيات** | وثائق المصادر، شروط الخدمة | سجل مصادر: ترخيص + تأخر + حقوق استعمال آلي لكل مصدر. **له حق منع** أي مصدر بلا حق واضح |
| **مهندس جودة البيانات** | تدفّقات خام | تقرير جودة لكل طلب + قرار `PASS/NO_TRADE` مع السبب |
| **مسؤول الاختبار والمحاكاة** | استراتيجيات مرشّحة | نتائج مع تكاليف كاملة، عدد صفقات، عدم يقين، ثبات عبر الأزواج |
| **مسؤول نماذج Kronos** | بيانات فوركس | مقارنة عمياء ضد خطوط أساس على بيانات بعد تاريخ النشر. **الافتراضي: وزن صفر** |
| **مسؤول الأمن والمراقبة** | النظام كاملًا | فصل المفاتيح، سجلات، تنبيهات، اختبارات الفشل |
| **مهندس التكاملات** | عقود المصادر | محوّلات (adapters) تُنفّذ العقد. **لا منطق تداول** |

### فريق التداول

| الدور | المدخل | المخرَج |
|---|---|---|
| **باحث فوركس وماكرو** | تقويم رسمي، بيانات ماكرو | تقييم نظام السوق + فرضيات مكتوبة **مسبقًا** |
| **محلل متعدد الأطر** | شمعات مُصادَق عليها | قراءة M15/H1/H4/D1 مع **درجة ثقة وحدود صريحة** |
| **محلل الأخبار** | Agent-Reach (مُعقَّم) | **وقائع مع رابط ووقت نشر** — لا توصيات. بلا `url`+`published_at` = مرفوض |
| **باحث استراتيجيات** | فرضيات | مواصفة استراتيجية مُصدَّرة، قابلة للاختبار، بإصدار |
| **حارس المخاطر (مستقل)** | كل ما سبق | `APPROVE` / `REJECT` + السبب. **نقض مطلق، لا يُستأنف** |
| **مسؤول التنفيذ** | صفقات موافَق عليها | أمر، أو `NO_TRADE`. **مُعطَّل الآن** |
| **مراجع ما بعد الصفقة** | توقّع + نتيجة فعلية | تصنيف سبب الخطأ + فرضية منافسة تُختبر. **لا يُعدّل حدًا** |

### حلّ الخلافات — قواعد صريحة

1. **لا تصويت.** الخلاف يُحلّ بالدليل أو يُحلّ بـ `NO_TRADE`. الأغلبية لا تُنتج صحة.
2. **حارس المخاطر فوق الجميع.** رفضه نهائي. لا يُستأنف ولا يُصوَّت عليه ولا يُلتفّ عليه.
3. **مسؤول الصلاحيات له حق منع** أي مصدر بلا حق استعمال واضح.
4. **تعارض البيانات** (مصدران مختلفان): `NO_TRADE` حتى يُحلّ. لا متوسّط ولا «الأرجح».
5. **تعارض التحليل** (إطار صاعد وآخر هابط): يُسجَّل كـ **عدم يقين صريح**، ويخفض درجة الثقة،
   ولا يُحسم باختيار الإطار الأنسب للفرضية.
6. **التعادل** في أي تقييم → `NO_TRADE`.

## 4. حواجز السلامة

| الحاجز | التطبيق |
|---|---|
| التنفيذ مُعطَّل | لا كود إنشاء أوامر إطلاقًا في هذه المرحلة |
| فصل المفاتيح | بيانات الوسيط لا تصل أبدًا لوكلاء البحث/الأخبار. `secrets/` في `.gitignore` |
| حدود المخاطر بملف يوافق عليه المستخدم | لا وكيل يكتب فيه. تغييره = التزام git موقّع منك |
| إيقاف فوري | حارس المخاطر يوقف كل شيء بلا موافقة أحد |
| سجل غير قابل للتعديل الصامت | git + بصمة لكل توقّع وقرار ونسخة استراتيجية |
| حظر الترقية التلقائية | الانتقال بين المراحل بموافقتك المكتوبة |
| منع تسريب المستقبل | كل حقل يحمل `info_available_at`؛ الاختبار يرفض ما لم يكن متاحًا لحظة القرار |
| حماية مجموعة الاختبار النهائية | مُقسَّمة ومُجمَّدة ببصمة؛ أي إعادة استخدام لتحسين استراتيجية = فشل مُسجَّل |
| مقاومة حقن التعليمات | مخرَج الأخبار موسوم `untrusted`، ولا يبلغ وكيلًا تنفيذيًا |

## 5. خطة المراحل

| المرحلة | المخرَج | معيار القبول | البوابة |
|---|---|---|---|
| **0. التدقيق** ✅ | تقرير + مصفوفة + 6 عيوب مُثبتة | أُنجز | — |
| **1. عقد البيانات والبوابات** 🔄 | عقد موحّد + بوابات + محوّل MT5 قراءة فقط | اختبارات تُثبت رفض كل عيب من الستة | تلقائي |
| **2. جودة التاريخ** | قياس العمق الفعلي، الفجوات، الشمعات الشاذة لكل زوج/إطار | تقرير بأرقام حقيقية: هل walk-forward ممكن أصلًا؟ | تلقائي |
| **3. محرّك الاختبار الرجعي** | محاكاة بسبريد عائم + انزلاق + عمولة + مبادلة + رفض أوامر | يُعيد إنتاج صفقة معروفة بدقة؛ يرفض أي بيانات غير متاحة لحظة القرار | تلقائي |
| **4. دورة البحث** | فرضية → رجعي → خارج العينة → walk-forward | استراتيجية مرجعية واحدة تعبر الدورة كاملة بأرقام صادقة | **موافقتك** |
| **5. تقييم Kronos** | مقارنة عمياء ضد 3 خطوط أساس | تفوّق معنوي على بيانات بعد تاريخ النشر، 5 أزواج، بعد التكلفة. وإلا: وزن صفر | **موافقتك** |
| **6. التداول الورقي** | محاكاة على بيانات حيّة بلا أوامر | أسبوعان متّصلان + اختبارات الفشل كلها تعبر | **موافقتك** |
| **7. مراقبة مباشرة بلا تنفيذ** | توقّعات مُسجَّلة مسبقًا، صفر أوامر | مطابقة التوقّع للنتيجة موثّقة | **موافقتك** |
| **8. مراجعة مستقلة** | مراجعة كود + أمان + إحصاء | لا مشكلة حاسمة مفتوحة | **موافقتك** |
| **9. تنفيذ حقيقي** | — | **كل ما سبق + قواعد شركة التمويل + موافقتك الصريحة المنفصلة** | **موافقتك** |

**موافقتك على البرومبت الأصلي ليست موافقة على المرحلة 9، ولا على أي مرحلة من 4 إلى 9.**

## 6. ما يُعاد استخدامه من المشاريع الخمسة

| المشروع | يُعاد استخدامه | يُرفض |
|---|---|---|
| **Kronos** | النموذج كمرشّح واحد، وزنه صفر حتى يُثبت | كمولّد إشارات |
| **Agent-Reach** | جمع الأخبار خلف مُعقّم | كمصدر أسعار أو أوامر؛ المستويات التجريبية |
| **claude-trading-skills** | أفكار إطار المخاطر: `drawdown-circuit-breaker`, `contrarian-setup-gate` (fail-closed), `trader-memory-core`, `signal-postmortem` | كل ما يعتمد على الأرباح/التوزيعات/13F/سعة السوق |
| **AI-Trader** | فكرة فصل الويب عن العمال الخلفيين | المنصّة، نسخ الصفقات، نظام المكافآت، «التصويت» |
| **tradingview-mcp** | لا شيء في مسار القرار | كمصدر بيانات لأي قرار أو اختبار |
